# ADR-005 — 멀티플레이는 별도 앱

- 상태: 승인
- 관련: [[ADR-003-flat-single-app-repo]], [[ADR-006-anticheat-scope]]

## 맥락

사업 모델(멀티플레이 대전 + 스킨 상점)이 예정돼 있다. 이걸 이 데모 코드베이스에
"진화"시켜 넣을지, 별도로 재개발할지가 이 repo의 미래대비 범위를 좌우한다.

## 결정

**멀티플레이 + 상점은 완전 별도 앱으로 재개발**한다. 이 repo는 무료 싱글 PvE 데모로
고정. 이 데모는 서버·통화·매치메이킹·복잡한 치팅방지를 **미래대비하지 않는다**.

두 앱의 유일한 연결 = **이식 자산**: 규칙 엔진(`src/game`), AI(`src/ai`), 렌더(`src/render`).
이들을 순수·클린 모듈로 유지해 앱2가 복사/재사용한다. 앱2 착수 시 공유 방식(복사 vs npm 배포)을 결정.

## 결과

- ✅ 지난 분석의 난제(모노레포·서버검증·통화 치팅방지·Firebase)가 전부 이 repo 범위 밖으로.
- ✅ 데모는 단순하게 출시, 앱2는 백지에서 최적 스택 선택(서버 권위 등).
- ⚠️ 규칙/AI/렌더를 클린 모듈로 유지하는 규율이 데모를 "막다른 길 아닌 자산생산기"로 만드는 핵심.

## Addendum — 로컬 hot-seat(동일 기기 다수 인간)은 본 ADR 비적용

- 상태: 승인 (docs/roadmap.md PHASE H, Local PvP 기획 시 확정)

이 ADR의 결정 근거(위 §맥락/결정)는 명시적으로 **서버·통화·매치메이킹·복잡한 치팅방지** 네 가지다.
같은 기기에서 여러 사람이 턴을 교대하는 hot-seat 대전(Local PvP)은 이 넷을 하나도 발생시키지 않는다 —
서버 왕복 0(ADR-001과 동일), 매치메이킹 없음(대기실 자체가 없음), 통화/상점 무관, 치팅방지는 개념이 성립하지
않는다(물리적으로 같은 자리에서 한 화면을 공유). 규칙 엔진(`src/game`)도 "입력 출처가 사람인지 AI인지"를
구분하지 않는 순수 함수라 로컬 다인 입력을 얹는 데 구조적 장애물이 없다.

**따라서 로컬 hot-seat 대전은 본 ADR이 규정하는 "멀티플레이(별도 앱)" 범위에 포함되지 않으며, 이 데모
(앱1)에 그대로 구현한다.** 네트워크로 연결된 원격 인간 대전(매치메이킹·서버 권위·통화)만 계속 앱2 소관이다.
