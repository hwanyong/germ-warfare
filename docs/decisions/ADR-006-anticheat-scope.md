# ADR-006 — 치팅방지 범위 (데모 = 최소)

- 상태: 승인
- 관련: [[ADR-001-fully-client-side-pve]], [[ADR-005-multiplayer-separate-app]]

## 맥락

웹 게임은 devtools(인스펙터)로 JS 상태·localStorage·네트워크를 편집할 수 있다.
완전 client-side라 스테이지 위조·룰 무력화가 로컬에서 가능하다. 유저가 이 검사를 요청.

## 결정

**이 데모의 치팅방지 ≈ 0.** 무료 싱글에서 자기 세이브 조작은 자해이고, client-side
치팅은 원천봉쇄 불가(난독화·무결성체크는 우회 가능한 보안극장 → 금지).

지금 하는 유일한 조치: **규칙 엔진을 시드 결정적으로** 만들기.
`map.mjs getMoveTarget` 동점 타이브레이크의 `Math.random` → mulberry32 시드 PRNG.

이유는 치팅방지가 아니라: (a) 데모 재현/디버깅, (b) 앱2 서버 권위 재시뮬의 전제조건.

## 두 위협의 구분 (앱2에서)

| 위협 | 서버 재시뮬로 잡히나 | 방어 |
|---|---|---|
| 룰 무력화 / 승부조작 (불법 수·상태 편집·위조 승리) | ✅ 잡힘 | 클라 move-log 를 서버가 깨끗한 규칙으로 재실행 → 불법 궤적 재현 안 됨 → 거부 |
| 정상 자동솔버 봇 (유효한 승리 로그) | ✗ 못잡음 | earn-cap / 에너지 / BUY-위주 통화 |

## 결과

- ✅ 데모에 보안 낭비 0.
- ✅ 시드 결정성(무료)만 적립 → 앱2가 서버 재시뮬로 룰 무력화를 잡을 수 있게 준비됨.
- 통화·구매·PvP 치팅방지(서버 권위 통화 + Cloud Function 구매: App Check + 멱등 receipt +
  익명차단)는 전부 앱2 소관. 데모에선 하지 않는다.
- localStorage 진행/전적은 append-only 원장으로 기록(가변 잔액 blob 금지) → 앱2 서버 권위 전환 시 무재작성.
